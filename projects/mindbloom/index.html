MindBloom

Small check-ins. Earlier support.

MY ROLE

Team contributor · AI-assisted development

TOOLS & METHODS

Lovable · React · TypeScript · Tailwind

PROJECT STATUS

4th place · $2,000 team prize

01

The idea

MindBloom explores how schools might notice repeated changes in a student’s well-being earlier. The idea brings daily check-ins, short wellness activities, and understandable signals into one supportive workflow.

02

What we built

The prototype includes mood, stress, energy, and sleep check-ins; journal reflections; guided breathing and grounding; a garden and streaks; and a counselor dashboard that explains the patterns behind a suggested check-in.

03

How we built it

We developed MindBloom as a team during UA Little Rock’s June 2026 AI Hackathon and HealthTech Startup Week. An earlier prototype used v0; the current version was built and iterated in Lovable with React, TypeScript, TanStack, and Tailwind. We used prompts, reviewed the generated interface, and refined behavior.

04

My contribution

I participated in the team’s development and iteration of the project. This was collaborative, AI-assisted work: Lovable generated and edited implementation code from our instructions. The repository preserves the build history and does not claim that I independently wrote every component.

05

The result

MindBloom placed fourth and received a $2,000 team competition prize. The current source is available on GitHub, alongside the live Lovable prototype.

06

What I am exploring next

I’m interested in making the prototype’s explanations clearer and distinguishing useful supportive signals from assumptions. Any move beyond demonstration would need careful evaluation with the people the system is intended to support.

Prototype scope: the dashboards use sample data and browser-local state. Calendar, wearable, and sign-in flows include demonstration features. The analysis uses explicit rules; this is not a trained diagnostic model or a clinically validated service.
